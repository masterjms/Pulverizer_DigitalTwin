# 발전소 미분기 디지털 트윈

석탄을 가루로 빻는 설비인 미분기의 상태를 3D 모델과 웹 화면으로 보여 주는 프로그램이다. ㈜넥스트로 디지털트윈팀 인턴십 기간에 개발했다. 이 저장소는 화면 설계와 구현, 3D 모델 생성 코드, 화면에 들어가는 데이터를 검증하는 도구를 담고 있다.

| 항목 | 내용 |
|---|---|
| 기간 | 2026.07 ~ 2026.10 |
| 역할 | 요구 분석, 화면 설계, 프론트엔드와 3D 연동 구현, 데이터 검증 도구 |
| 기술 | React, TypeScript, Vite, Unity WebGL, Python, SQLite |

## 1. 문제 정의

초기 요구는 "설비를 3D로 보여 주고 부품의 남은 수명을 표시한다"였다. 화면 구성에는 정답이 없어 무엇을 넣고 뺄지 판단할 기준이 필요했다.

같은 화면을 두고 사용자마다 묻는 것이 달랐다. 경영진은 비용과 운영 목표를, 현장 작업자는 부품 단위의 이상 징후를 원했다. 따라서 문제를 화면 배치가 아니라 **"누가 이 화면을 보고 어떤 결정을 내리는가"가 정의되지 않은 것**으로 보았다.

## 2. 설계: 세 단계의 정보 깊이

사용자를 셋으로 나누고, 화면을 세 개 만드는 대신 하나의 3D 모델을 한 단계씩 들어갈수록 더 세밀한 정보가 나오도록 설계했다. 세 사용자는 같은 데이터를 서로 다른 크기로 묶어서 볼 뿐이기 때문이다.

| 단계 | 3D 모델 | 대상 | 화면이 답하는 질문 |
|---|---|---|---|
| 외형 | 설비 여섯 대의 겉모습 | 의사결정권자 | 어느 설비가 가동 중인가, 목표와 비용은 어떤가 |
| 절개 | 선택한 설비 한 대의 단면 | 운영자 | 이 설비의 부품은 언제 교체해야 하는가 |
| 분해 | 부품을 펼친 모습 | 현장 작업자 | 어떤 일이 이 부품을 이렇게 만들었는가 |

| 절개 | 분해 |
|---|---|
| ![절개](Evidence/ce883/cutaway.png) | ![분해](Evidence/ce883/exploded.png) |

- 역할에 따라 화면을 잠그지 않는다. 누구든 끝 단계까지 들어갈 수 있다.
- 단계를 오가도 보고 있던 시점은 유지된다.
- 분해 단계의 시간 막대를 움직이면 3D 모델의 색, 당시 운전 값, 정비 기록이 함께 바뀐다.
- 그래프의 이벤트 점을 선택하면 해당 시점과 부품으로 이동한다.

## 3. 데이터 표시 원칙

이런 화면에서 가장 위험한 것은 그럴듯해 보이는 숫자다. 화면 구현에 앞서 다음 원칙을 정했다.

| 원칙 | 내용 |
|---|---|
| 결측 표시 | 값이 없으면 없다고 표시한다. 0이나 정상으로 대체하지 않는다. |
| 설비 격리 | 한 설비의 기록을 다른 설비에 복제해 채우지 않는다. |
| 가상 데이터 구분 | 시험용 데이터는 사용자가 직접 열어야 나오며, 여는 동안 화면 상단에 안내를 유지한다. |
| 과거와 미래 구분 | 과거 기록의 재생과 미래 계산을 화면에서 분리한다. |
| 인과 단정 금지 | 같은 시각에 일어난 두 가지 일을 원인과 결과로 표시하지 않는다. |
| 계산 위치 단일화 | 수명과 교체 시점은 화면에서 다시 계산하지 않는다. 화면은 받은 값을 표시만 한다. |

## 4. 원칙의 구현: 데이터 계약과 테스트

원칙을 문서에만 두지 않고 코드가 지키게 했다.

- 화면이 받는 데이터의 모양을 타입으로 정의했다.
- 들어온 데이터는 화면에 그리기 전에 검사한다. 설비 이름이 요청과 다르거나, 부품 수가 맞지 않거나, 숫자가 아닌 값이 섞이면 거부한다.
- 테스트 이름은 원칙을 한 문장씩 옮긴 것이다. 이름만 읽어도 화면이 무엇을 약속하는지 알 수 있다.

테스트 예시

- 다른 설비의 데이터가 섞여 들어오지 않는다
- 값이 없는 것과 마모가 0인 것은 다른 색으로 보인다
- 기준 시각보다 뒤의 기록은 읽지 않는다
- 오래된 상태를 현재 값처럼 유지하지 않는다
- 비용이 늘어난 것을 줄어든 것으로 바꾸지 않는다

## 5. 실제 기록의 연결과 검증

엑셀로 받은 운전 기록을 화면이 읽을 수 있는 형태로 옮기는 도구를 만들었다.

- 옮기기 전과 후의 모든 값을 순서대로 비교해 일치 여부를 확인한다. 값 하나나 시각 하나가 달라져도 검출한다.
- 옮긴 저장소는 읽기 전용으로 연다. 화면 쪽 코드가 기록을 수정할 수 없다.
- 확인되지 않은 항목은 추측으로 채우지 않고 확인이 필요한 항목으로 문서에 남긴다.

이 과정에서 발견한 사항

- 팀이 실제 기록으로 알고 있던 데이터베이스는 받은 파일과 기간이 다른 별개의 시험 데이터였다.
- 켜짐과 꺼짐만 있어야 할 상태 값에 중간 값이 섞여 있었다. 내보내는 과정에서 평균 처리된 것으로 추정했다.
- 같은 항목의 단위가 설명서와 파일에서 서로 달랐다.

고객사의 운전 기록 원본과 원본 문서는 이 저장소에 포함하지 않는다.

## 6. 3D 모델과 화면의 연동

- 모델은 코드로 생성한다. 부품 치수를 코드에 두어 모델, 화면 구성, 검증을 한 번에 다시 만들 수 있다.
- 화면과 모델은 부품 이름으로 연결한다. 화면에서 위치를 선택하면 모델의 같은 위치가 선택되고, 그 반대도 같다.
- 모델은 받은 값에 따라 색만 칠한다. 계산은 하지 않는다.
- 모델은 설비 구조를 이해하기 위한 시각적 근사이며 제조 도면이 아니다.
