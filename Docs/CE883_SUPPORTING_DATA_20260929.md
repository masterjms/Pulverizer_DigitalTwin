# B 미분기 추가 자료 검토 — 2026-09-29

## 검토 결과

사용자가 제공한 ZIP의 5개 파일과 별도 운전시간 HWP를 읽었다. 원본 파일은 수정하지 않았다. 복사본과 원본 SHA-256 목록은 `Data/document-review/sources/`, `Data/document-review/manifest.json`에 보관했다. ZIP 내부 파일명은 복사본에서만 NFC로 정규화했다.

검토용 `Data/document-review/staged-records.json`에 마모 측정값 90개, 소비탄 일자 151개, 정비·운전 이벤트 4건, A~F 운전시간 집계를 정리했다. **검토용 자료이며 현재 React/Unity의 실측 마모·수명 계산에는 아직 연결하지 않았다.** 현재 연결된 B 운전 데이터는 기존 2025-12-10~19 자료 그대로다.

## 1. 롤타이어 마모도

원천: `sources/2026/3호기 미분기 #B 마모도 측정 결과 (26.3.27).xlsx`, Sheet1.

- 측정일: 2025-06-09, 2025-08-13, 2026-03-27.
- b-1, b-2, b-3 각각 위치 1~10: 3회 × 3롤 × 10위치 = 90값.
- 위치 헤더 C2:L2. b-1은 C3:L5, b-2는 C7:L9, b-3는 C11:L13.
- 최신 행 B5/B9/B13의 롤 식별자는 비어 있다. 앞선 행과 표의 묶음으로 귀속했으며, 검토용 기록에 이 추론을 표시했다.
- 최신 값 범위는 6.15~59.6. 시트에는 단위, 신품 기준면, 마모량인지 잔존 두께인지에 대한 명시가 없다. 기존 화면의 50 mm 한계와 직접 비교하거나 백분율로 환산하지 않는다.
- **‘차이’ C6:L6, C10:L10, C14:L14는 2025-08-13 값에서 2025-06-09 값을 뺀 수식이다. 2026-03-27 값은 반영하지 않는다.** 최신 마모 증가량으로 수입하면 안 된다.
- 일부 위치는 이후 측정값이 줄어든다. 측정 방향·기준면 변경, 부품 교체·보수 여부를 확인하기 전 단조 증가 마모 곡선으로 강제 보정하지 않는다.

확인할 내용: 단위/측정 정의, 위치 1→10의 실제 방향과 Unity 구역 매핑, 롤 번호의 실제 배치, 설치·교체 기준일, 2025/2026 측정 방식의 동일성.

## 3. 소비탄 분석결과

원천: `sources/2026/2026년 3호기 소비탄 분석결과.xlsx`.

- 실제 표시 시트는 `25.12 월 소비탄`, `26. 1월 소비탄`, `26. 2월 소비탄`, `26. 3월 소비탄`, `26. 4월 소비탄`의 5개다. 2026년 5월 시트는 없다.

- 151개 실제 달력 일자 중 석탄사용량 수치가 있는 날은 147개. 3월 4~7일은 B열에 ‘급전정지’, 수치 칸은 빈 값이다. 빈 값을 0 실측으로 바꾸지 않았다.
- 탄종·혼합비, 사용량(톤), 총수분, 발열량, 고유수분, 휘발분, 회분, 고정탄소, 미연탄소분, 황분이 있다. 저위발열량은 월별 열 제공 여부가 다르고 표기 단위도 별도 확인이 필요하다.

- 숨겨진 2020년 자료/계산 보조 시트 13개가 함께 들어 있다. 일부 수식 오류가 있다. 2025~2026 실데이터 수입 대상으로 삼지 않았다. 실제 표시 5개 시트의 저장값에는 Excel 오류 셀이 없었다.
- 계산된 셀은 수식과 저장값 출처를 검토용 기록에 보관했다. 원본 재계산은 수행하지 않았다.

이 파일에서 발전 목표 MWh, 전력·연료 가격, 정비·부품 비용은 확인되지 않았다. 석탄사용량은 발전 목표량이 아니다. AMWI 계산에 필요한 모든 성상·모델 입력이 갖춰졌는지는 별도로 검증해야 한다.

## 4. 분급기 회신

원천: `sources/2026/미분기 운영데이터 Classifier 질의 회신.xlsx`, Sheet1 C3:D7, G2:I9.

- D3: 설정 0%=0 RPM, 100%=166 RPM.
- D4: Actual RPM은 Classifier 실제 회전부 기준.
- D5: Bias는 운전원 직접 입력 ±10%.
- D6: PID 제어 (25.9.29~). Bias 자동계산을 묻는 조건부 질문에 대한 짧은 답변이므로, 이것만으로 전체 제어식과 보정 순서를 확정하지 않는다.
- D7: 인버터 및 V-Belt.
- G4:I9: 급탄량/급탄기 요구/Classifier Demand의 6점 대응표.

설정 백분율과 실제 회전수는 별개다. 설정값을 RPM으로 환산한 값을 실측 RPM으로 표시하지 않는다. 실제 운전 파일의 `3HFC20CS011XM01` 태그가 회신의 Actual RPM과 일치하는지 확인한 뒤 기존 raw 필드의 단위를 확정한다. ‘첨부2.’ 텍스트가 있으나 해당 통합문서 ZIP에 `xl/media/` 이미지 파일은 없었다.

## 5. 운전시간 집계

원천: `sources/미분기 운전시간 산출.hwp`. 본문과 내장 페이지 미리보기 확인.

- A~F 집계가 모두 있다. 다만 실시간 운전 센서가 아니라 과거 운전시간 집계다.
- 2025-08~12 및 2026-01~05 표. 2026년 5월은 한 행만 있다.
- B 문서 합계: 앞 표 3,369.93, 뒤 표 2,778.08. 합산 6,148.01.
- A~F 모든 표의 수치 합산이 문서 ‘계’와 일치했다.
- 제목은 운전시간이나 별도 단위와 산정식, 가동 판정 기준, 매월 3개 행의 정확한 시작·종료일은 명시되지 않았다. 시간(h) 해석은 확인이 필요하며, 6,148.01을 설치 이후 누적 수명으로 사용하지 않는다.
- 기존 12월 10일~19일 연속가동 240 h는 12월 B 두 번째 행의 240과 수치상 같다. 행의 기간이 명시되지 않아 동일 구간 검증 완료로 보지는 않는다.

## 6. Pyrite 처리 횟수

원천: `sources/2026/2026년 3호기 미분기 Pyrite 처리횟수.hwp`.

A~F와 D/N 열을 가진 표가 있으며 본문에서 12월·2월·3월·4월·5월 표를 확인했다. 1월 표는 찾지 못했다. 문서명은 2026년이지만 12월 행의 연도는 표에 명시되지 않아 2025년으로 자동 확정하지 않았다. `-`, ‘정지’, 병합 셀이 존재한다. D/N의 정확한 교대 시간과 기호 의미를 확인해야 한다. 처리 횟수만으로 정확한 이벤트 시각을 만들어 그래프의 점으로 표시하지 않는다. 원본과 본문을 보관했고, 병합 표를 단순 순서로 펼쳐 B 횟수를 자동 수입하지 않았다.

## 7. 나머지 운전 엑셀 연결 순서

1. 20개 파일은 재압축·엑셀 병합 없이 원본으로 한 폴더에 저장한다. 먼저 파일 목록으로 시작/종료 기간을 조사한다.
2. 우선 2026-03-27 측정 전후 파일, 다음 2026-02-13 Runback 전후 파일을 받아 기존 B 태그/단위와 비교한다. 정비·측정 이벤트 연결을 작은 범위에서 먼저 검증한다.
3. 파일마다 실제 최초/최종 시각, 간격, 행 수, 결측·중복, 태그 및 단위, 해시를 기록한다. 파일명 날짜만으로 범위를 확정하지 않는다.
4. 동일 시각·동일 값은 중복으로 관리하고, 동일 시각·상이한 값은 충돌로 남긴다. 후입력 값으로 묵시적 덮어쓰기를 하지 않는다. 시간대·상태 코드·누락 구간을 검증한다.
5. 검증된 원본은 초 단위로 보존하고 UI 표시용 요약은 분리한다. 파일별 완료 기록으로 재개 가능하게 만든다. 기존 단일 파일 import는 기존 캐시 덮어쓰기를 거부하므로 20개 파일을 그대로 반복 실행하지 않는다. 별도 배치 수입 기능이 필요하다.
6. 마모 정의와 설치/교체 기준을 확인한 후 실측 보정과 수명 계산을 연결한다. 비용·발전 목표 자료는 별도 입력이 필요하다.
