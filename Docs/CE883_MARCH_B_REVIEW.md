# B 미분기 2026년 3월 운전 파일 검토

검토일: 2026-09-29

## 결론

제공 파일은 기존 B 자료와 같은 14개 태그의 12일치 데이터다. 3월 27일 마모 측정 이력과 시간상 부합하는 급탄·모터 신호 감소 및 회복을 확인했다. 파일을 읽어 로컬 검토용 캐시에 저장하고 모든 값을 대조했다. React/Unity에서 사용하는 기존 12월 데이터는 교체하지 않았다.

상태 코드의 소수값과 코드 20 때문에, 연결 시 가동·정지를 0/1로 단순 해석하면 안 된다. 또한 1초 간격의 내보내기 자료라는 사실은 매초 독립적으로 취득한 원시 센서 데이터임을 보증하지 않는다.

## 운전시간 문서와 수치 일치

12일 중 상태값이 정확히 1인 행은 1,012,021개다. 각 행을 1초 표본으로 집계하면 **281.116944시간 → 소수 둘째 자리 281.12시간**이다.

앞서 받은 `미분기 운전시간 산출.hwp`의 2026년 3월 B 세 번째 행도 **281.12**다. 수치가 일치하므로 해당 집계와 이번 파일이 대응할 가능성을 뒷받침한다. 다만 HWP에는 세 번째 행의 날짜 경계와 산정식이 명시되지 않았다. 이 일치만으로 원천 집계의 전체 산정 규칙을 확정하지 않는다. 설치 이후 누적 운전시간이나 잔여 수명으로도 사용하지 않는다.

## 연결 전에 처리할 항목

### 상태 값과 보간

원본 헤더 E9:R9는 `TimeAvg`, 통합문서 설정은 `ReportType=Fixed step`, `StepSize=1S`다. 모터 상태가 네 구간에서 각각 91초 동안 소수로 변한다. 디지털 상태 코드가 평균/보간 처리된 것으로 의심되며, 원천 내보내기 방식을 확인해야 한다.

모터 상태별 표본 수:

- 1: 1,012,021개.
- 4: 6,208개.
- 20: 18,207개.
- 소수값: 364개.

기존 `입력데이터셋 설명_ 미분기_20260604.xlsx` Sheet1 G4/K4는 기동 1, 정지 4, 나머지 Fault로 설명한다. 따라서 20을 정상으로 표시하면 안 되지만, 현재 자료만으로 코드 20의 구체적 원인이나 실제 고장을 확정하지 않는다. 보간된 소수값 역시 실제 Fault 이벤트 364건으로 세지 않는다.

현재 `Tools/local_b_data.py`의 표시 어댑터는 정지를 0으로 판정한다. 새 파일을 연결하기 전에 정의서의 4 판정과 미확인·보간 상태 처리를 보완해야 한다. 이번 검토에서는 실행 코드를 수정하거나 데이터를 교체하지 않았다.

배출밸브는 실제 파일에서 0/1 및 소수값이 나타나며 정의서의 닫힘 4와 다르다. 임의로 0=닫힘을 확정하거나 밸브 값 변화를 Pyrite 처리 횟수로 바로 세지 않는다.

정확한 이벤트 시각이 필요하면 상태/밸브 태그를 원시 변경 이력 또는 값 유지 방식의 디지털 내보내기로 요청하고 코드 정의를 확인하는 것이 적절하다. 기존 엑셀의 소수값을 반올림해 원시 상태를 복원했다고 주장하지 않는다.

### 단위 및 수명 계산

모터 태그는 정의서에서 A이지만 운전 파일 G3에는 CU.M/H다. 분급기 실제 속도 L3은 비어 있다. 앞서 받은 분급기 회신과 정의서는 실제 회전부 RPM을 설명하므로 이를 매핑 근거로 사용할 수 있으나, 적용 시 출처와 단위 충돌을 명시해야 한다. 값의 이름만으로 소비전력·전력 비용을 계산하지 않는다.

이 파일 자체에는 마모량·롤 교체 기준일·정비 비용·발전 목표 컬럼이 없다. 3월 27일의 30개 위치별 측정값은 별도 마모 파일에서 날짜로 연결할 수 있다. 단위·측정 기준·위치 매핑 확인이 필요하며, 이번 파일로 마모율·교체 권장일 검증이 완료된 것은 아니다.

기존 12월 파일과 이번 3월 파일 사이의 기간은 미수령 상태다. 두 파일을 연결할 때 사이 기간을 선형 보간하거나 연속 실측 구간으로 표시하지 않는다.
